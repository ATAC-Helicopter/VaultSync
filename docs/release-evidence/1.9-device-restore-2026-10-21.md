## Delivered and remaining boundary

An internal engine consumes a sealed image, exclusively owned already-held target
and durable-journal provider. It validates exact image/capture/generation/root,
operation/review correlation and equal target geometry, re-verifies the entire
stage, then orders durable intent → bounded write → target flush → durable range
acknowledgement. Full target content/GPT read-back precedes WrittenAndReadBack.
Failures retain the acknowledged prefix and an uncertain interval; there is no
rollback, resume or completed-system claim. Target cleanup failure is a failure,
not success. A failed terminal journal append is reported as unconfirmed.

The Linux x64 adapter adopts a matching existing block descriptor with O_RDWR and
FD_CLOEXEC, rejecting ordinary files, append/direct mode and observed busy/unsafe
geometry. It does not open a target or prove authority/exclusivity/offline state.
There is no public/elevated writer endpoint, desktop/media path or production
journal opener. The only native caller is the private disposable-VM harness.
The [contract](../RAW_DEVICE_RESTORE_1.9.md) retains required future broker/role,
image sandbox, device/offline and repository/journal ancestry/consent boundaries.
