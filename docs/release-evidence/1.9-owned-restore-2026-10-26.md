## Implemented behavior

The internal [owned operation](../LINUX_RAW_RESTORE_OPERATION_1.9.md) connects
sealed staging ownership, exact expiring review, fresh inventory, private durable
journal, exclusive native acquisition, the real writer/read-back and cleanup.
The attempt is consumed once. Concurrent duplicate requests cannot cancel or
dispose the active owner. Abandonment, timeout, cancellation and faults release
all resources and retain acknowledged/uncertain ranges and journal outcomes.
An unconfirmed close cannot become overall success. Correlation IDs still grant
no human/device/offline authority; no new public elevated endpoint is introduced.

A real 3 GiB OS capture exposed small authenticated remote reads in the second
payload digest. An independent 2 MiB probe measured **512 × 4 KiB requests** with
generic stream hashing, versus **16 × 128 KiB** with the existing exact-length
reader, with identical SHA-256. The worker and its trusted warmup now use that
reader. Protocol budgets, kernel sandbox/peer checks, deadlines and refusal paths
remain unchanged. Each pass rereads bytes; no stale payload cache is introduced.
This is a request-count result, not a throughput or supported-capacity claim.

## Source-bound native loop

The source VM boots Debian 12 in UEFI with a GPT/ext4 disk and three hash-bound
fixture files, including nested paths and spaces. Its cleanly stopped **3 GiB**
ordinary-file backing is exposed read-only to a separate pinned recovery guest.
Capture publishes a verified, sealed image on a separate ext4 repository.

The recovery guest is restarted without the source disk. It independently stages
and verifies the retained image, creates the exact native target review, executes
the owned operation against a new equal-capacity virtual disk, flushes the journal
and target, reads back every byte and closes every owner. Independent journal
reopening confirms ReadBackVerified for all **3,221,225,472 bytes**. Replay refuses.

After shutdown, the host hashes both whole disks: restored target equals the
original source byte for byte, and the source hash is unchanged. A further VM
boots only the restored disk with fresh firmware variables and a read-only seed:
no source, image repository or recovery OS is attached. UEFI/ext4 startup passes
and all three fixture hashes equal the originally recorded source values.

Separate native fault runs use tiny synthetic GPT sources with **512/4096-byte**
sectors. Injection performs one real native sector write, then raises an I/O
exception or cancellation. All four targets retain exactly that first sector;
results report zero acknowledged prefix and the full pending chunk as uncertain.
Persisted journals independently report Failed/Interrupted. Native exclusive
claims reopen after cleanup and no automatic retry occurs. These are controlled
faults, not physical power cuts or full-OS interruption qualification.

The runs contain **64 named native assertions** (capture 5, restore 13, fault 46),
plus separate restored-boot/filesystem/hash checks. Source/capture use normal
QEMU process exit receipts. Detached restore/boot/fault guests separately record
zero guest markers, QMP-confirmed shutdown, accepted quit and daemon termination;
no unobserved daemon exit code is invented. Network, shared folders and host raw
devices are absent. Only disposable ordinary-file-backed virtual disks are written.

## Failed attempts retained separately

- The initial cloud-kernel IDE seed was undiscoverable; a virtio seed corrected
  private source preparation. This was not an application failure.
- The first full capture copied all bytes then refused final inspection, without
  publishing completion. The bounded digest fix then passed the same source.
- A tool-session interruption stopped staging. The target independently remained
  blank. The private state was retained and the lab restarted with detached VMs.
- One private postcheck appended an incorrect `.journal` directory suffix after
  native write/read-back/cleanup had passed. The target already matched the source,
  but that harness run remains failed. The path was corrected and the entire
  restore rerun on another blank target; the clean run passes all checks.

Large failed/interrupted repository artifacts were losslessly archived with
round-trip SHA-256 verification. Earlier source variants and failures never count
as final success. The official cloud-image HTTPS SHA-512 matched before use;
its PGP signature was not verified, and no release publisher attestation is claimed.
