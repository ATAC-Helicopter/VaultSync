## Persistent workflow

`./dev audit --release <owning-version>` is now required before tracked pushes.
`--all-releases` checks the complete family. The command is read-only and reports
missing/duplicate owners and board entries, exact milestone/labels, assignee,
roadmap priority, native status/Area/Release and traceable dates. It checks the
Project account as well as number. Partial memberships/fields and API failures
cannot produce a passing result. The JSON report omits issue bodies.

AGENTS.md, CONTRIBUTING.md and WORK_TRACKING.md specify creation/adoption before
implementation, synchronized status at start, incremental evidence and closure
criteria, actual completion dates and the tracking audit before pushes. The
standard applies across releases without moving feature ownership. Historical
evidence and implementation-complete but unreleased work remain distinguishable.
