## Behavior implemented

- Existing page commands, tray/onboarding calls and saved `LastView` values use
  the page-only typed route coordinator/adapter. No legacy page is removed.
- The header has Back/Forward, disabled when unavailable, and Alt+Left/Right.
  Labels/tooltips are supplied in all 19 existing language files. History is
  bounded, held in memory and cleared after initial saved-page restoration.
- The initial route uses configuration already loaded by startup, eliminating
  the later callback that could redirect a user after their first click.
- A single writer serializes last-page saves and coalesces intermediate queued
  visits to the newest one. A slow earlier save cannot finish after the latest
  save. Error reporting does not strand later writes. This does not serialize
  unrelated config writers or guarantee an outstanding save on forced shutdown.
- History keeps unfinished label/note/tag drafts when refresh replaces the same
  project/snapshot row. Clean drafts follow refreshed metadata. Another snapshot,
  another project or no selection loads its own metadata rather than inheriting
  the draft. Save/clear normalization does not overwrite edits made while saving.
- Project cards separate names from snapshot statistics on two lines, preventing
  names from losing all available width when narrow or without a snapshot.
  Missing snapshot size text is hidden instead of duplicating the time label.

## Native UI qualification

An isolated Linux X11 test application renders the real `App`, `MainWindow`,
view models, compiled bindings and themes from the candidate source. It uses
dedicated VAULTSYNC_CONFIG_DIR and XDG config/data/cache directories under
`/tmp/vaultsync-shell-runtime-20261009`, with two synthetic projects and one
real CLI-created metadata snapshot of a 52-byte fixture file. There is no backup
payload and no disk image; History correctly labels the snapshot Metadata only.
The installed user's stable application and its data are not the test target.

Toolbar command bindings and native X11-injected Alt+Left/Right traverse
Projects → History → Settings → History → Settings, retaining the cached History
instance and its search text. A successful new Projects visit clears forward
history. Startup resumes Projects without an implicit Dashboard history entry.
The first attempt to synthesize a routed KeyEvent directly did not exercise
Avalonia's native keyboard binding path; it is not counted as success. Native
X11 key injection passed afterward. A coordinate-based pointer attempt did not
navigate and is not counted as mouse qualification; toolbar command bindings
were executed in the rendered window instead.

The first native forced-refresh attempt reproduced a deeper draft-loss cause:
ListBox collection replacement temporarily cleared its bound selection, discarding
the draft before identity reconciliation. The final implementation suppresses
those callbacks during replacement, then resolves and re-notifies selection.
A regression simulates the collection-change callback, including empty results.
The repaired native path retains an unfinished label through forced refresh,
toolbar Back/Forward and native Alt+Left/Right. A 920×720 candidate window
shows the existing collapsed sidebar and the new header controls.

Final native recapture confirms both project names remain readable in the
920×720 window, with one missing-snapshot label rather than duplicate statistics.
The isolated configuration's actual saved `LastView` is Projects at completion.
