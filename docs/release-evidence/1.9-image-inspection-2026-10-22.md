## Delivered boundary

The real worker executable now supports a separate internal Linux x64 reader.
Its parent brokers bounded byte reads of two caller-held read-only streams; no
file/device path, shell, executable, credential or native image/device handle
crosses the wire. After trusted module-owned warmup, the child drops root to
UID/GID 65534, verifies zero capabilities, disables dumpability, sets no-new-
privileges/limits and installs a default-deny seccomp allowlist with all-thread
TSYNC. Nonroot launch preserves matching nonzero caller identities.

Content/layout verification and a second full-payload SHA-256 run in that child.
A fixed binary summary contains only bounded facts, not reason text or raw
content. Parent-side kernel task-state checks, exact peer lifetime, terminal ACK,
stdout EOF, empty stderr and exit zero precede usable return. Late error output
or partial/early/nonzero completion never becomes a successful observation.
See [complete contract](../IMAGE_INSPECTION_WORKER_1.9.md).

This is an operating reader component, not completed production isolation.
Current staging and the restore engine still parse in their caller. Mandatory
reader-first staging, exact immutable-byte binding, writer integration and trusted
installed worker/role/protocol review remain required. The summary is not origin,
authorization, offline proof, a sealed image or device consent. No desktop/media
route, elevated writable operation or release package is introduced here.

## Investigated attempts, kept separate

Private artifacts are under
`/Users/flavio/Developer/vaultsync-validation.nosync/image-inspection-20261022`.
The linked JSON identifies each retained prefix/source artifact.

- Early bootstrap refused the CLR's anonymous JIT mapper and loaded assembly
  descriptors. The accepted mapper now requires exact anonymous identity, zero
  links, ownership, close-on-exec and tmpfs; writable regular files/devices remain
  forbidden. Descriptor checks precede privilege reduction so trusted installation
  files remain traversable. No W^X or unsafe-compiler workaround was used.
- A trusted embedded synthetic corpus initializes parser/crypto/async dependencies
  before policy entry. Untrusted image bytes remain unread until after entry;
  there is no post-entry filesystem-open exception or unsandboxed fallback.
- A CLR task retired during parent observation. New complete stable task snapshots
  are bounded to three attempts; missing/unreadable/unsafe tasks never pass partly.
- Some workers aborted with a misleading `Out of memory` after computing a result.
  Private stderr and a Debian strace probe identified denied
  `sched_setaffinity(0, ...)` during CLR thread initialization. Pinned runtime source
  confirms that failure aborts thread creation. The filter now permits only that
  current-thread operation; positive/foreign/high-bit cases have regressions.
  CPU metadata path opens remain denied. Increasing memory headroom alone did not
  fix this abort; those failed attempts are not described as successful evidence.
- Native/data allocation budgets now include existing CLR reservations and reject
  oversized baselines instead of lowering limits below existing reservations.
  They are not cgroup resident-memory guarantees or large-image measurements.
- The first successful 27-case source precedes final cleanup extraction and the
  added running-cancellation/deadline cases. Only the final 30-case source is
  current evidence; debug/traced/intermediate runs are not summed into it.

Raw stderr, syscall traces and descriptor listings stay private and are never
