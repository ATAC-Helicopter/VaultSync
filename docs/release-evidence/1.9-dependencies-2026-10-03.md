# Dependency reduction audit — 2026-10-03

This first pass removes one unused direct/resolved package and fixes coordinated
updates without losing used functionality. It is not a claim that all replaceable
libraries have been rewritten. Baseline: 30 centrally pinned packages; after the
unused-font removal: 29. The three LiveCharts packages are the largest bounded
application-owned replacement candidate.

| Package group | Source consumers / dependency evidence | Decision |
|---|---|---|
| Avalonia, Desktop, Wayland, Fluent | App startup, windowing, controls, native Wayland fallback, XAML styles | Keep the desktop framework and supported platform behavior |
| Avalonia.Controls.ColorPicker | SettingsView has two live ColorView bindings and App includes its theme | Keep; a replacement needs HSV/RGB/alpha, accessibility and keyboard qualification |
| Avalonia.Fonts.Inter | No WithInterFont registration, font resource URI or code consumer; plain family name resolves installed fonts | Removed direct reference and central pin; actual app keeps bundled Noto/system fallbacks |
| LiveChartsCore.SkiaSharpView.Avalonia + two transitive LiveCharts packages | Dashboard storage donut and stacked backup-usage graph are visible; weekly activity already uses native controls | Candidate for native Avalonia drawing with preserved colors, sorting, proportional geometry, responsive layout and legends; no deletion before replacement |
| SkiaSharp and HarfBuzzSharp managed/native packages | Avalonia.Skia and Avalonia.HarfBuzz require both families; LiveCharts also consumes SkiaSharp.HarfBuzz | Keep aligned security/ABI overrides; chart replacement could remove SkiaSharp.HarfBuzz if restore graph confirms no remaining consumer |
| Skia/HarfBuzz WebAssembly native assets | Avalonia explicitly requires these transitively even in the desktop dependency graph | Removing direct pins does not remove resolved packages and risks mixed ABI versions; retain coherent pins |
| Dapper | Metadata repository uses query/execute/scalar mapping throughout data paths | Keep for this pass; a narrow reader/parameter adapter is technically possible but needs schema/null/transaction regression evidence across all call sites |
| Microsoft.Data.Sqlite and SQLitePCLRaw bundle | Metadata, history, project registration and migrations; explicit bundle overrides older transitives | Keep maintained database engine and security pin; do not rewrite SQLite |
| System.Security.Cryptography.ProtectedData | CredentialVault Windows DPAPI enrollment and retrieval | Keep OS-backed credential protection; do not replace it with application cryptography |
| Spectre.Console / Spectre.Console.Cli | All CLI routes, tables, error/help output and command contracts | Keep coordinated API upgrade; handwritten parsing must preserve published behavior and completion contracts before removal |
| CommunityToolkit.WinUI.Notifications / System.Drawing.Common | Windows notification backend; Drawing override services legacy toolkit transitive | Existing VS-1928 in 1.9.8 owns notification migration; remove the legacy cohort only after native Windows delivery |
| Microsoft.NET.Test.Sdk, xUnit, analyzers and VS runner | Build, test discovery, CI and assertions | Keep development-only tooling; VS-1929 in 1.9.8 owns test platform modernization |

Before removal, inspect project.assets.json and runtime publish output, not only
direct PackageReference counts. Native ABI and security overrides are intentional.
Replacing visible charts must be validated with empty/single/multi-project data,
large values, sorting, resizing, light/dark/custom themes and actual screenshots.
The current build/test qualification does not establish this visual replacement.
