# Compression structure iteration — 2026-10-15

Owner: VS-1996 / issue #786 / preparation PR #736. Research only; ZIP remains
the production archive format. No beta, recovery or performance gate is closed.

## Scope and originality

This original implementation groups ASCII decimal lexemes by bounded preceding
byte context, stores their widths and encodes per-context integer differences.
It tries extraction of 1–18 or 4–18 digit runs and selects a smaller complete
frame only. The general ideas of structure/value separation and delta coding
are established; this work does not claim a new entropy family or verified novelty.

Prior art/reference links: [XMill, Liefke/Suciu (2000)](https://sigmodrecord.org/publications/sigmodRecord/0006/pdfs/XMILL_%20An%20Efficient%20Compressor%20for%20XML%20Data..pdf),
[Zstandard dictionaries](https://github.com/facebook/zstd/blob/dev/README.md),
[Brotli dictionary transforms](https://github.com/google/brotli/blob/master/c/enc/static_dict.c),
[Finite State Entropy](https://github.com/Cyan4973/FiniteStateEntropy).
Only the paper/principles were consulted; no third-party implementation is copied.

Generated fixtures only, each split into the same 128 KiB independent blocks.
Every reported measurement restores the exact fixture bytes. All prototype
outer/inner framing and transform metadata are counted. Zstd uses its content
checksum; none of these measurements include archive paths, encryption or I/O.

| guid-heavy-yaml | 116,324 | 112,549 | 92,739 | 79,680 |

The numeric JSON fixture is deliberately favorable: small changing counters and
regular fields are not a representative mixed project. It shrinks from 75,775
to 6,413 prototype bytes (91.5%), below raw Zstd 3 on that generated case.
The same transform plus zlib 6 needs 1,630 bytes, showing the transform helps
but the custom entropy/match backend still leaves substantial room for improvement.
For generated Unity YAML the custom result is 15.2% smaller than the prior
prototype; for source code it is 7.5% smaller. Zstd remains denser and much
faster on these ordinary text and GUID-heavy fixtures. No universal win is claimed.

The full transforms of several maximum-sized blocks exceed the conservative
128 KiB transformed-stream budget and are skipped. Smaller tail blocks or the
4-digit policy can still benefit. A future bounded multi-part transform needs
a separately reviewed reader/resource design; silently raising limits is not done.

Speculative classification/encoding costs CPU even when rejected: on already
deflated bytes new encode median is about 70 ms versus 22 ms for prior Huffman;
GUID-heavy encode is about 238 ms versus 123 ms. Numeric JSON decode improves
from about 196 ms to 75 ms, while native Zstd is still far faster. Python versus
native timings are diagnostic under uncontrolled host load, not implementation
promotion evidence. Use the linked JSON for exact medians and source/fixture hashes.

## Safety and current validation

Blocks are capped at 128 KiB, contexts at 32 with 64-byte keys, numeric runs at
18 digits, and varints at nine bytes. Overflow contexts share the last lane;
original widths preserve leading zeros. Non-numeric bytes, NULs, binary bytes,
signs, decimal punctuation and line endings retain their original spelling.
Decoder checks header/lane bounds, canonical integers, exact consumption,
output limits, signed-value fit and plaintext/encoded hashes. Mode 3 allows
one structural layer only; nested structural frames are rejected. Unkeyed hashes
detect corruption, not malicious origin. Total archive and authenticated integrity
contracts remain prerequisites before any production integration.

Twenty-four compression tests pass, including a hand-written independent lane
fixture, 32-context overflow, raw fallback, randomized/boundary byte equality,
malformed streams with valid frame checksums, truncation and recursion refusal.
The optional reference is zstandard 0.25.0 / libzstd 1.5.7 installed in a temporary
venv, not an application dependency. Report base is ba85d4443bb461f3292124e89df85c4e3b72d2ce
plus the recorded working tree/source hashes. Rider tools are unavailable;
