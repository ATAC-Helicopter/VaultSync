## Continued implementation — VS-1974

Three regression cases reproduced the old watcher dry-run defects before the
fix: snapshot-only preview waited until cancellation, sync/verify preview failed
against an untransferred target, and an absent store was initialized before the
missing-project failure. The initial release-branch full suite also had one
watcher timeout (1,025 passed, 1 failed); the accumulated stack already contains
startup-observation and test synchronization fixes, so those were retained.

`watch --dry-run` now validates options, reads configuration without saving
defaults, opens an existing database read-only, reports intent and exits. It
does not start watching, scan/hash/index files, transfer or verify bytes, create
the destination or migrate a database. Opt-in `--output json` returns one v1
`watch.plan` envelope without paths; live JSON is explicitly rejected before
database access. Invalid debounce and missing sync destinations are also rejected
before access. Missing project/source guidance now goes to stderr in text mode.

A plan checks registration and source-directory existence. Its false
`destinationChecked`, `transferToolChecked`, `payloadChecked`, `watching` and
`recordedBackup` flags state the evidence boundary. Private CLI logging remains.
Earlier development scripts expecting a persistent dry-run session must now
remove `--dry-run` to start live watching. The handbook, output/audit contracts,
task guide, release docs, roadmap, changelog, generated help and completion agree.
