## Delivered increment

The solution now builds a separate `VaultSync.DiskWorker` executable. It accepts
exactly one fixed 32-byte inventory request followed by EOF, validates version,
operation and nonempty operation UUID before observation, and rejects trailing
data after consuming at most one extra byte. There are no caller-supplied paths,
commands or device selectors. The fixed Core observer opens only Linux sysfs/proc
metadata; unsupported platforms return an explicit typed result.

The response binds the operation UUID and bounds JSON to 1 MiB before emitting
its header. The host applies a 30-second application deadline; inherited standard
pipes need not honor cooperative cancellation for its wait to finish. Refusal,
timeout, access/encoding/I/O and unexpected exceptions have numeric exits without
private exception diagnostics. No visible UI text or locale key was added.

This is process separation, not authentication, elevation, OS sandboxing or write
permission. The executable is absent from product launchers and release/updater
assets. Exit zero means transport completion, not a successful observation or
safe destination. There is no product response consumer. No image or device is
opened, captured, overwritten or qualified by this increment.

inherited pipes. On the final macOS build all 13 scenarios pass: a correlated
UnsupportedPlatform response, five truncations, trailing byte, second request,
unknown version/operation, empty UUID, rejected arguments and missing-EOF timeout.
The latter exits 124 after 30.074 seconds, with no output or diagnostic text.
The probe only passes `/dev/never-open-this` as a rejected argument; it never
opens that path. This is transport testing, not macOS disk support.

The private self-contained Linux x64/.NET 10.0.13 publish also passes all 13
process scenarios in QEMU 11.1.1/Q35/UEFI. The inventory is Observed: the 3 GiB
source is in use through mounted descendants; separate 128 MiB targets report

The normal response is 3,078 bytes; missing EOF exits 124 in 30.419 seconds.
The guest powers off normally with exit zero, no timeout and no VM left running.
Total boot plus probes is 194.40 seconds, not an inventory throughput result.

The Linux publish preceded two final host exception-to-exit handlers (invalid
data and unexpected exceptions); exact host source/binary hashes are separate
in the structured report. Its protocol and Core observer match final source.
The Linux run does not qualify those final exception handlers. Final source
passes the full Release suite and the repeated macOS process probe above.

The pinned Debian source and firmware are the same inputs as the earlier
