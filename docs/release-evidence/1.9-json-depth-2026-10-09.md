## Observed failure and correction

At head `9d5c88f7679ddbebd94d540374553e03f477fae9`, hosted Windows,
macOS and Linux build/test jobs and CodeQL passed. Script tests in
[run 37963334712](https://github.com/ATAC-Helicopter/VaultSync/actions/runs/37963334712)
and the Python coverage step of
[Sonar run 37963334812](https://github.com/ATAC-Helicopter/VaultSync/actions/runs/37963334812)
failed `test_excessive_json_nesting_has_an_explicit_refusal` because a ValueError
was not raised. This is a repository test/implementation failure, separate from
historical Sonar PR-discovery errors. Local Python 3.12.3 had passed the fixture;
CI selects `3.x`. The previous implementation relied on the decoder raising
RecursionError rather than enforcing an explicit metadata depth limit.

The checker now rejects nesting above 64 object/array containers, counting the
root. An iterative preflight tracks JSON string/escape state before decoding,
ignoring braces and brackets inside keys and values. Existing JSON syntax,
duplicate-key, finite-number, UTF-8 and bounded-read checks remain authoritative.
No recursion setting is changed and no device/engine operation is added.

Three added regression tests cover the inclusive 64/65 boundary for arrays and
objects, escaped delimiters/quotes/backslashes, and malformed syntax rejection.
The existing 10,000-container refusal fixture now uses the explicit bound.
