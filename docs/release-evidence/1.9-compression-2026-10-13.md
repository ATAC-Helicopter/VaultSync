## Whole ZIP measurements

[ZIP report](1.9-compression-zip-2026-10-13.json): one warmup, five measured
iterations, exact entry readback each time; timestamps fixed. The current policy
calls the production resolver. Explicit Fastest is the previous level for these
Unity extensions on identical fixtures. Byte sizes include ZIP file metadata.

| Generated fixture | Logical bytes | Previous Fastest ZIP | Current policy ZIP | Saving | Encode median, previous → current |
|---|---:|---:|---:|---:|---:|
| Scene + prefab text | 1,958,360 | 250,608 | 167,260 | 33.3% | 1.78 → 8.85 ms |
| 2,000 small `.meta` files | 480,000 | 611,529 | 562,062 | 8.1% | 9.83 → 14.45 ms |

Optimal costs about five times as much encode time on the scene fixture; it is
not a throughput improvement. SmallestSize yields 141,586 bytes there but takes
12.61 ms, so this iteration chooses the more moderate existing Optimal level.
The small-file archive is still larger than its logical contents: per-file ZIP
headers and paths dominate. Grouping small files is a future format experiment,
not a claim made by the current change. SmallestSize saves only another 2,324
bytes for this metadata fixture.

Binary `.asset` retains Fastest; known `.zip` remains Store. Generated random
bytes are proxies, not real Unity binary assets or media. The profile shows
Fastest expansion on that proxy; avoiding this through content sampling is a
separate measured iteration. No broad binary policy change is justified here.
P95 is the maximum of five samples and managed allocations omit native memory.
These local memory ZIP tests do not measure real upload, peak process memory,
installed restore or Endless Drive. Existing archives were not touched.

## Own codec results

[Prototype report](1.9-compression-prototype-2026-10-13.json): deterministic
generated fixtures, up to 128 KiB independent blocks, five measured iterations
after warmup; every decoded byte compared with the input.

| Fixture | Logical bytes | Prototype v0 bytes | zlib level 6 bytes |
|---|---:|---:|---:|
| Unity YAML | 486,480 | 75,999 | 38,181 |
| Source code | 426,490 | 54,726 | 25,943 |
| Random proxy | 524,288 | 524,612 | 524,472 |

The custom v0 is less dense than DEFLATE on these fixtures. It includes 81
framing bytes per block; zlib includes its stream wrapper. Neither is a complete
archive comparison. The random proxy selects raw storage in v0: payload does
not expand, framing still adds 324 bytes over four blocks. Timings compare a
Python implementation with native zlib and cannot qualify a native codec speed
claim. The already-deflated synthetic stream still contains compressible
structure; it is not evidence that recompressing real media is useful.

The next research step is entropy coding and bounded match search, then an
independent native decoder. No custom writer, codec identifier, container
extension or runtime dependency is added to the application.
