## Delivered boundary

A private mode-0700 Unix listener precedes child launch. The parent binds the
actual launched PID and its effective UID/GID; the child binds its kernel parent
and matching effective UID/GID. Both use the existing socket-bound pidfd lease.
An explicit startup phase precedes the correlated pipe request. The child waits
for acceptance after writing the bounded reply, staying alive while the parent
validates it and rechecks the peer. EOF, no extra stdout, empty stderr and exit
zero remain required afterward. Linux x64 refuses missing/unsupported peer binding
without a pipe-only fallback. Other platforms retain the existing development
transport. No raw-device operation, privilege or desktop/media path is added.
See the [full protocol contract](../DISK_WORKER_1.9.md#inventory-peer-integration--2026-10-21).
