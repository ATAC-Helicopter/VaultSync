## Delivered scope

Internal Linux x64 Unix-stream binding compares an expected process ID and
connect-time UID/GID to kernel SO_PEERCRED and obtains SO_PEERPIDFD from that
same socket. It pins the exact peer task rather than reopening a numeric PID.
Unsupported options, mismatch, closed connection or dead peer refuse; acquisition
rechecks the identity and liveness after obtaining the lease. The pidfd must have
FD_CLOEXEC. Poll is nonblocking; no process data, signal or foreign file is read.

Rechecks consume no application bytes and permanently invalidate on failure.
Disposal closes only the owned pidfd, exactly once, while retaining the caller's
socket. The handle wrapper accepts a valid zero descriptor; lifetime polling
holds a SafeHandle reference to prevent disposal/reuse during the native call.
Internal synthetic providers are not selectable by wire or image input. No
persistent IDs, raw identifiers or text errors enter application diagnostics.

This is a peer primitive, not trusted build/installation selection, per-message
sender authentication, current credentials after transition, human consent,
privileged role, offline proof or device-write permission. The current inventory
client/executable still use their development pipes; no product listener,
launcher integration or writable command is introduced. The [worker contract](../DISK_WORKER_1.9.md#kernel-peer-binding-prerequisite--2026-10-21)
records inheritance/queued-closure limits and remaining integration.
