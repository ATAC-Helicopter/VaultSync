# Raw payload verification evidence — 2026-10-13

Owner: VS-1917 / #574. Preparation PR: #736. This is a bounded read-only
increment, not a verified disk image or recovery qualification.

`DiskImagePayloadVerificationService` first requires a complete logical map.
It then streams every declared raw part, checks exact length and SHA-256, and
rejects missing, truncated, trailing or altered bytes. It never opens a device,
path or destination and allocates one 128 KiB buffer rather than an image-sized
buffer. The caller retains ownership of each supplied stream. The focused cases
cover exact data, mutation, truncation, trailing bytes, missing completion,
missing parts, malformed digest, cancellation and a huge declared length with
an immediate refusal before any stream read. Misaligned raw lengths also refuse
before reading.

The positive synthetic part is 512 bytes (`00` through `ff`, repeated twice)
with independently calculated SHA-256
`110009dcee21620b166f3abfecb5eff7a873be729d1c2d53822e7acc5f34eb9b`.
The logical map also contains an explicit zero sector. This verification does
not reconstruct that zero sector or validate the full image. Supplied digests
are not yet bound to an image manifest/completion root, trusted source or
later restore operation; `PayloadsVerified` cannot authorize a destination.
