## Implemented boundary

Linux raw staging now requires the fixed adjacent isolated reader for both the
initial input and the private sealed copy. The parent snapshots bounded metadata
and supplies a non-owning read-only view of mutable caller input; this first view
is explicitly not sealed. An invalid/unsupported/corrupt result or unavailable,
failed, timed-out, absent or malformed worker result refuses before allocation.
No in-process parser fallback exists. The input itself chooses no output path,
storage provider, executable, operation, native descriptor or device authority.

After exact bounded copy/EOF and file flush, native storage seals 0400 and reopens
the same inodes read-only, closing all transaction-owned writable descriptors.
Only then does the second isolated parse run. Every canonical summary field,
including whole-payload SHA-256, must match the first result. Parent-side bounded
hashing binds the exact snapshot metadata SHA-256/length and observed payload
SHA-256/capacity before publication. It hashes bytes without interpreting image
records. Changes between input, copy, seal and reader summaries cannot produce a
usable session under these checks.

The session's public assessment contains IDs/generation/root/capacity and separate
bounded logical/physical geometry. It carries no declared origin/tool strings or
parser-owned coverage/layout graph. Original metadata bytes remain unchanged in
the protected copy; these observations are not authenticated provenance.

Preview and native acquisition compare those bounded geometry fields. Before
Started, the internal writer hashes exact held metadata and payload again. After
writing, exact target read-back SHA-256 must equal the reader-verified payload
hash. Neither staging nor the writer reparses hostile metadata/GPT in its caller.
Target byte equality carries the already checked GPT bytes without claiming
filesystem recovery or a bootable OS. Journal/native ordering, uncertain ranges,
target disposal and the lack of writable authority remain unchanged.

## BUG-19036: measured stale-buffer defect

The controlled-owner-mutation native probe found 128 KiB read buffers on sealed
native FileStreams could retain bytes across seeks. Changed metadata refused
before writes, but a changed 512-sector payload yielded **Failed / one write /
target closed / four journal fixture records**: final hash refused success after
writing had begun. This was not successful corrupted recovery, but admission
should observe the current held inode before Started.

Read-only native reopens now disable managed read buffering; transfer callers
already own bounded buffers. Preserve exact inode/device/UID/link/size, 0400,
close-on-exec, no-follow and durable publication checks. A permanent native
ordinary-file regression primes a read, performs a controlled owner write, seeks
and requires the new byte. Final staged native mutation tests require **Refused,
zero writes, zero journal records and closed target** for both metadata and payload
at 512/4096 geometry. No same-UID/admin compromise containment is claimed: a
malicious administrator can still interfere after checks. Exclusive trusted
ownership and the future operation authority/lifetime boundary remain required.
