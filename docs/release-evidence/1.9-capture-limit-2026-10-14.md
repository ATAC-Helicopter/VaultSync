# Synthetic capture resource limit — 2026-10-14

Owner: BUG-19031 / #789. Preparation: `work/1.9-roadmap-realignment`, sole
draft PR #736 into `Dev`. Previous head: `89b25542`; the verification below
concerns the capture-limit implementation tree, not historical release checks.

The synthetic file capture accepted aligned capacities through `long.MaxValue`,
while reconstruction accepts at most 1 GiB. A large supplied stream could fill
temporary storage even though its capture could not be reconstructed by this
fixture pipeline. Capture now shares reconstruction's 1 GiB limit and returns
`Invalid` / `capture.fixture-size-limit` before source reads or workspace creation.
This bound is a fixture resource policy, not a supported disk-capacity limit.

Two regression cases failed before the correction: requests of 1 GiB plus one
512/4096-byte sector created a workspace, consumed the small source and returned
`Incomplete`. After correction, those requests are refused without reads, bytes
written, workspace or manifest root. Two exact-limit cases retain normal source
truncation refusal using empty input, without allocating gigabyte-sized files.
All 18 capture tests pass without skips, including independent encoded fixtures,
round-trip verification, source failures and cancellation. Logs:
`/tmp/vaultsync-toolchain/capture-before.log` and
`/tmp/vaultsync-toolchain/capture-after.log`.
