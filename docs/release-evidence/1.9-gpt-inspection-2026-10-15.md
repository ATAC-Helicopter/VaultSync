## Implementation and integration

A read-only inspector validates the single protective first MBR entry, paired
GPT revision 1.0 headers, checksums and reciprocal locations, disk/usable bounds,
128-byte entry arrays, unique partition GUIDs, reserved attributes and ranges.
Partition ranges cannot overlap each other or metadata. Both entry copies must
match exactly even when their CRCs agree. Unknown revisions, oversized/extended
entry arrays and hybrid/legacy MBRs refuse without fallback or automatic repair.

Geometry is limited to 512/4096 logical sectors. At most 1,024 slots are admitted;
total metadata reads are at most 274,432 bytes, independent of source capacity.
Bounds are checked before metadata seeks/allocation. The API owns no path or
stream, writes nothing and restores the input position. I/O/cancellation propagate;
short metadata is incomplete. Output enums are technical results, not UI text.

Layout observations include disk/partition IDs, exact byte ranges and raw
attributes, plus a versioned metadata SHA-256 fingerprint. Names are not exposed.
The fingerprint binds geometry, complete MBR/header sectors and both entry arrays,
not partition contents or gaps. Matching GUIDs do not establish physical identity;
CRC/content hashes do not authenticate a producer or authorize writes.

Independent fixtures are generated using Python struct, uuid little-endian GUID
encoding and zlib CRC32. The C# fixture mutations use a separately implemented
non-reflected CRC calculation. A constructed pair of different entry arrays with
equal CRCs is refused. Fixture sources and outputs are synthetic and contain no
captured user information. Regenerate with `python3 scripts/generate_gpt_fixtures.py`.

Both golden geometries run through capture → reconstruct → GPT inspection using
existing file services. Whole-source SHA-256 and metadata fingerprints agree after
reconstruction; the original stream is not needed for reconstruction. Outputs
are temporary regular files cleaned by the tests. No physical device is opened.

Field references: [UEFI GPT specification](https://github.com/UEFI/UEFI-Specification-Release/blob/main/source/05_GUID_Partition_Table_Format.rst),
[EDK II field definitions](https://github.com/tianocore/edk2/blob/master/MdePkg/Include/Uefi/UefiGpt.h).
The inspection admission limits are VaultSync policy, not universal GPT support.

## Beta impact and limits

The maintainer requests a complete-feature beta in the coming days. Compression
experiments are deferred while the disk/recovery path is developed. This increment
advances raw layout inspection; it does not complete serialized source/layout/build
records, native adapters, worker authorization, desktop integration or independent
recovery media. There is no filesystem/EFI executable in these fixtures and no
boot proof. Zero disk-support profiles are qualified. Existing architecture,
installed upgrade, signing, hosted-check and actual recovery gates remain open.
