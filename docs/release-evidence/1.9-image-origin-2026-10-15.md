## Integrated path

Explicit GPT-file capture now inspects a seekable source at position zero,
validates source/tool inputs before reads where possible, and copies/hashes it
into an exclusive temporary workspace. After flushing the copied raw part,
it inspects the copy and refuses a changed GPT fingerprint before manifest or
completion publication. The 1 GiB fixture limit remains unchanged.

The new provisional schema-2 origin record stores source/observation UUIDs,
physical sector claims, writer-observed UTC milliseconds, full GPT partition
observations and tool version/source commit claims. The root binds that record
alongside the complete map and part digest. No names, source paths, serials or
secret fields are added. Schema 1 remains readable; the existing generic capture
entry point still writes schema 1. Old readers reject the new manifest schema;
no shipped production image migration or stable serialization is introduced.

Parsing bounds and validates canonical text, timestamps, geometry, used-entry
counts, IDs, ranges, reserved fields, exact lengths and the supported whole-raw
map before payload access. Unknown origin versions/kinds refuse. The only source
kind currently accepted is regular-file fixture; it is not native disk capture.

Generic ContentVerified proves supplied raw streams match manifest digests; its
DeclaredOrigin remains untrusted claims. Reconstruction additionally checks GPT
metadata fingerprint, disk ID, usable bounds and every partition against actual
reconstructed bytes. Even a self-consistently rehashed false layout cannot
report successful reconstruction. Refused diagnostic files can remain but do
not receive successful state or a returned content digest.

Tool/source claims cannot be authenticated with unkeyed hashes. An explicit test
changes the source commit and recomputes completion: parsing succeeds as claimed
metadata, without conferring producer trust. Real source consistency, trusted
worker/build provenance and destination identity/authorization remain separate.
No host device is opened or written and no user-facing application string is added.

## Independent and adversarial checks

Python struct/UUID/SHA-256 code independently encodes both 512/4096 schema-2
metadata fixtures, using the earlier independently generated raw GPT fixtures.
Regeneration is byte-exact. Golden records are verified and reconstructed;
production fixture writing also completes the full capture/verify/reconstruct
path at both geometries. No source database or original source stream is needed
for reconstruction.

32 new cases include malformed/unsupported origins, counts, timestamps, text
padding/control bytes, commits, partition overflow/overlap/identity/reserved
fields, early no-read/no-workspace rejection, cancellation, missing root binding,
false layout claims with valid hashes and mutation between initial observation
and copy. Existing schema-1 raw/zero/mixed and failure fixtures remain passing.
The unknown future manifest test advances to schema 3 because schema 2 is now
explicitly understood; existing golden schema-1 bytes are unchanged.
