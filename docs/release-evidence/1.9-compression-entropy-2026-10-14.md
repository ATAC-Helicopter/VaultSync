# Canonical Huffman compression iteration — 2026-10-14

VS-1996 / #786, preparation PR #736. Second isolated research iteration;
production archives still use compatible ZIP. See [design](../COMPRESSION_EVOLUTION.md).

## Implemented

An original canonical Huffman encoder/decoder compresses the existing bounded
LZ77 token stream. The writer compares complete payloads, including a 264-byte
entropy header/codebook, and keeps raw or plain LZ when smaller. The original
LZ77 encoder remains available as the baseline. No application writer, backup
container, codec identifier, native dependency or updater behavior is changed.

Draft mode 2 remains disposable experiment framing. Encoded SHA-256 binds the
codebook and payload; decoded SHA-256 verifies final plaintext after both stages.
Unkeyed hashes are corruption checks, not attacker authentication. The entropy
reader bounds tokens at 132,096 bytes and code lengths at 24 bits, rejects
oversubscribed/incomplete tables, invalid single-symbol tables, truncated or
trailing bitstreams, nonzero padding and excess/missing decoded symbols.
Existing LZ distance/output checks still run after entropy decoding.

## Measurements

[Report](1.9-compression-entropy-2026-10-14.json): Python 3.9.6 on native macOS
27.2 Arm64, generated fixed-seed fixtures, one warmup and five measured
iterations; exact readback after every measurement. Source hashes bind codec,
entropy implementation and harness to a dirty worktree based on 8ff4333.
Runtime servicing validation and sibling builds were active in this session;
background load/power mode was not controlled. Timings are diagnostic, not a
dedicated-machine speed qualification. Byte sizes are deterministic.

| Generated fixture | Logical bytes | Plain LZ77 v0 | LZ77 + Huffman | Saving vs v0 | zlib level 6 |
|---|---:|---:|---:|---:|---:|
| Unity YAML | 486,480 | 75,999 | 54,394 | 28.4% | 38,181 |
| Source code | 426,490 | 54,726 | 36,502 | 33.3% | 25,943 |
| Random proxy | 524,288 | 524,612 | 524,612 | 0% | 524,472 |

Huffman improves our first prototype's density but remains larger than zlib
level 6. The straightforward Python bit decoder also costs more: generated YAML
decode median 33.77 → 150.71 ms and code decode 27.98 → 105.40 ms. YAML encoding
58.21 → 81.09 ms; code encoding 48.11 → 63.62 ms. These are Python prototype
measurements, not a fair runtime comparison with native zlib or .NET ZIP.

Random input selects raw storage after trying both codecs, so payload does not
expand; four frames still add 324 bytes. Trying entropy increases encode time
356.30 → 500.98 ms there, which motivates measured classification/early exit
work. An already-deflated synthetic stream is not representative media. Complete
backup metadata, network I/O, concurrency and native peak memory are not measured.

reader with golden/differential tests. Native restore throughput and memory must

builds and does not establish complete-feature beta readiness.
