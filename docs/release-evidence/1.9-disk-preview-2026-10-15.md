## Behavior

The immutable preview binds operation ID; image ID, generation, lowercase
SHA-256 manifest root and declared capacity/sector size; containing repository
device ID; and exact destination registration, generation and hardware identity.
It names the whole-disk overwrite range `[0, image.Capacity)` without summing
untrusted unsigned bounds. Supported geometry is equal-size 512/4096-byte disks.

Every refusal returns no preview. Unknown/ambiguous identities, empty IDs,
nonphysical targets, unknown/in-use mount state, read-only/unknown write state,
repository on target, mismatched or invalid geometry and smaller targets refuse.
Larger targets also refuse: GPT backup-header relocation remains unqualified.
Rechecking performs all current checks and compares every binding; a changed
operation, image, root, repository, target, hardware identity, capacity, sector
size or generation invalidates the previous selection even if otherwise safe.

These records carry caller-supplied observations; they are not trusted hardware
evidence or a serialized worker protocol. There is no authorization-success state:
`PreviewOnly` means a description exists. The image contents are not verified by
this service. The future native adapter must resolve repository physical ancestry,
aliases and ambiguous identities, then re-observe through the opened handle.
The service cannot prevent device substitution after its final call. UI, native
worker, explicit consent, content verification, interruption evidence and joint
architecture approval remain required before writes.

Enums are internal technical outcomes with no new user-visible strings or UI
integration. When displayed, they require translated mappings in every locale.
The existing file-backup destination identity service is unchanged.
